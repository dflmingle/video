# Web 特效实现与编码可见性

在 Web/Three.js 项目需要实现参考已有的重要视觉事件时使用；无此需求不新增特效系统。参考事件发现与保真分账属于 video-replication；本文件只说明已经运行验证的渲染/录制方法。方法已在固定场景中验证，不宣称通用三维恢复、跨浏览器像素一致或量化性能收益。

## 坐标、挂点与显示适配

- 区分源帧像素、分析画幅、配准坐标、对象局部坐标、世界坐标与最终屏幕像素。记录裁切/缩放、轴向、单位、root变换及使用的相机时刻；将挂点和路径投影回最终画面核对，不能只看数值相近。
- 起点使用实际加载对象的挂点，经过显示缩放、朝向与父变换。当前方法验证过按姿态取模型局部点再转到世界；不把依赖特定模型颜色/顶点的挂点提取当通用算法。
- 在已标定二维映射下，将源路径反变换再相对实际起点平移；起始点与末端分别核对。为保持旧布局而适配目标点时另记修正向量和显示目标ID，不能把邻近对象认作真实命中因果或改变伤亡。源方向/速度因适配改变，保真须降级，不能只验终点到达。
- 本次没有验证任意透视、移动相机下逐帧反投影或真实三维弹道；不将固定映射推广到这些情况。

## 轨迹、拖尾与生命周期

以输出绝对时间求 `age = t - event.start`，用带时间的路径样本插值位置；持续以事件数据为准。局部相邻时刻的位置差可确定短尾方向/长度，当前验证的是紧凑移动实体加短尾，不是任意长烟带或流体求解器。不同视觉类型不应共享不适合的短瞬时模板。

按各阶段自己的起止求透明度、尺寸、扩散与消散；允许阶段重叠。每次求值重建活跃实例数、矩阵和实例透明度，避免依赖墙钟累计；起点动作如后坐从该时刻基础姿态应用，避免叠加漂移。用顺序与乱序时刻渲染比较像素/状态，覆盖开始、传播、结束和回退，而非只核时间标签。

## 小尺寸亮芯、透明度与混合

- 在最终输出画幅检查投影像素宽度和亮芯覆盖。宽柔光贴图缩小时可能只剩弱透明边缘；对参考中的紧凑光体，独立RGBA紧凑核加柔光/短尾已验证能保留可见性。它不是所有效果的推荐外形，不自动提高亮度或统一改加法混合。
- 当前实现分别用加法光层与普通透明烟层，禁用透明面的深度写入并为实例提供独立alpha属性。按参考核对透明背景、亮背景、图标覆盖和缩小编码后的表现；不能只设共享材质opacity导致整批同显同隐。
- `renderOrder`、`depthWrite` 与 `depthTest` 解决的问题不同；同一场景排序不能覆盖后续独立渲染的图标/UI。先定位实际最终合成顺序，再改局部层级。
- 验证过的局部方案是独立场景在指定图标层后合成，保存并恢复 `renderer.autoClear`，仅该命中层关闭深度测试；这会盖住图标/削弱物理遮挡。只有参考和产品层级支持时采用，并核对root/相机变换，不把全特效置顶或全局禁深度当默认修复。

上述亮芯、尺度和分层在组合方案中验证改善；未保留单参数中间成片时，不声称某次改高度/透明度单独解决了问题。

## 实例容量与保护性集成

实例化平面、矩阵和alpha属性按层复用，输出前更新实际count及buffer标记；重叠事件计算容量，超限显式报错，不能静默丢弃后半段特效。当前仅验证这种实现能稳定渲染，未测GPU/FPS提升，不能写成性能收益结论。

独立模块/数据及开关便于逐层定位。关闭新层后对照原成片的像素及受保护状态；开启后核查最终合成与既有事件同存。可视后坐等显示变化不改权威成员位置、状态或伤亡。画面可见不证明因果正确，两者分别核验。

## 编码后逐事件核对

1. 加载当前资源完成后按统一 `n / outputFps` 录制，所有轨迹、动画、透明度和残留共用该时间；不以墙钟推进效果再截图。
2. 源片/输出帧率不同，对照明确选择源帧及重置时间戳，显式声明CFR输出；核实帧号对应关系、实际帧数和时长。不能把编码成功当时间对齐证明。
3. 在最终MP4而非浏览器截图上查看事件之前、起始、传播、结束、消散的连续证据；只验参考存在的阶段，未知不补造。记录全幅与局部，检查位置/方向、大小、亮度、速度、持续、遮挡与压缩损失，覆盖全片尤其后半段。
4. 每条分别记录程序触发、编码可见性与参考保真。无事件、错误时空或缺失参考明确阶段为FAIL；部分失真为PARTIAL；未查为UNKNOWN；参考确认不适用为N/A。不以事件数、draw调用、实例数或预览非空代替视觉PASS。
5. 三方对照标清原片、原始最终版、当前修复；上一修复另命名。验收绑定最终MP4哈希和实际查看范围；全局 reviewed 标志不能把未看的事件转为PASS。帧序列、预览和最终编码一致性与确定性是独立检查。

参考有明确长尾/烟带而当前方案仅短尾时，必须继续实现相应阶段或如实报告缺口；不能把本文件“短尾已验证”用作省略要求的理由。
