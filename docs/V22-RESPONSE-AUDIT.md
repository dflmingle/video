# V22 局部战斗响应与红方软凝聚

本分支只负责期望响应偏移及红方软约束；蓝方根节点积分、动画、箭矢、相机和完整渲染由主分支集成验收。

## 实际根因

- `tools/build_simulation_v21.py` 已经存在真实箭矢命中：impact 时对 red-local target 调用 `motion.apply_hit`，并写入 damage、remainingHP、killed。此前“没有命中/击杀事件源”的结论错误。生产系统缺少的是**蓝方受到攻击**的事件源，不能用虚构伤害代替。
- `motion_v21.Crowd.compute_desired_speed` 在 `motion_v17` 已完成逐人伤口减速后再次乘 `speedMultiplier`，造成重复伤口惩罚。V22 直接继承 V17，只保留一次伤口模型。
- `motion_v21.Crowd.compute_local_avoidance` 的 `min(1,limit/.20)` 对 `.20–.34` 的 limit 恒等于 1。V22 实际限制横向速度 / 当前前向速度，正常 `.20`，真实绕行 `.30`，继续保留 V17 接触求解器。
- `motion_v17.compute_desired_speed` 远距离容许 `2.5+5*pressure` 的纵向误差且只最多修正 `.30` 速度，持续个体速度差很难被整理。V22 不硬写位置，改为有限死区、近处放宽的软加速度，未修改 preferredSpeed 或 strideBase。

## 接口与集成

`CombatResponseV22(blue_units, starts=None, config=None)`，别名 `CombatResponse` 和 `Response`。

1. 在现有真实箭矢 impact 结算后调用 `record_impact(e['shooter'], redLocalTarget, damage, killed, t)`。target 必须是红方局部下标，不是全体 units 下标。
2. 每固定帧调用 `offsets(t, bluePositions, dt, redPositions)`，或同签名 `update`，取得 nblue×2 `combatResponseOffset`。
3. 将返回值作为蓝方部署目标之外的**期望偏移**传给 Agent A 的弹簧/碰撞积分。它不是本帧位移，禁止直接每帧累加到根位置。
4. 无事件时输出为零。命中激活射手及最多两名同组、近距离的前排邻居。hit 主体峰值意图 `.135`，kill `.205`；邻居乘 `.55`。事件方向锁定为当时射手到命中目标的方向。
5. `.12s` 起势，`.20s` 保持，`.40s` 指数尾，`.42s` 冷却。叠加取最大而非求和，输出范数硬限 `.235`；不会整队推进或随命中数无限累计。
6. `record_damage(archer,damage,t,diagnostic=True)` 只供显式诊断退让，审计标记 `DIAGNOSTIC_BLUE_DAMAGE`。省略 diagnostic=True 会抛异常。生产完整片不得插入此类事件，除非后续存在真实蓝方伤害源。

`motion_v22.Crowd` 沿用 V17 唯一权威 `step`：固定 60Hz、独立位置速度、独立步态、空间哈希、`.615` 身体最小距离、倒地者静态占位、无反向位移断言均保留。修复后的远/近横向自由度 `.18→.54`，纵向明显超前死区 `1.15→2.80`；横向加速度限 `2.4`，纵向仅对明显超前者施加最多 `-2.2` 的小幅修正，乘 dt 后进入目标速度，仍由 V17 原加速/转向限制器处理。伤者不被纵向编队弹簧拉回队伍。实际压力仍取小方阵前沿到蓝方位置的世界距离。

## 发现并修复的 V22 红方速度回归

最初提交的 `.20s` 前向速度 servo 是本次引入的错误。它在原本受限加速度外又增加一层速度低通，前排启动延迟又经真实拥挤查询向后排传播。参数 `redSpeed=21.75` 没变，不能据此宣称实际冲锋速度保持。

按 `redChargeStart` 对齐，原 V21 与有回归的 V22-C 在启动后 `.6s` 的健康 median 前向速度分别为：红 `21.075→6.884`，橙 `21.077→5.617`，黄 `21.443→8.963`；`.6s` 累计世界路径分别为红 `7.102→1.841`，橙 `6.774→1.496`，黄 `7.592→2.567`。这不是正常的个体差异。

消融证据：关闭 formationAcceleration、保留 servo 后，`.6s` 红/橙/黄仍只有 `7.041/5.750/9.039`；同时恢复 V17 原 limiter 后达到 `21.063/21.114/21.448`。说明主要根因是额外 servo，而非软编队压力。

最小修复移除了该 servo，完整复用 V17 limiter；只保留加速度乘 dt 的小目标修正，纵向只整理明显超前者，不拖慢健康后排。新增 `tools/diagnose_red_speed_v22.py` 在相同 ID、seed、60Hz、蓝方位置和无命中条件下比较 V21/V22 的 `.6/1.2/2.0s` 每色速度、世界路径和启动时间；另以无拥挤单兵验证加速曲线逐值一致。

旧 V22-C 相对 V21 的交战窗口 `.4333→.7167s`，其中安全结束相对冲锋启动延后 `.2667s`，首次命中仅提前 `.0167s`。这部分收益主要来自错误变慢，不能冒充射击改善。旧 V22-C 视频/安全结束时间需在修复后重新生成，不能沿用。
