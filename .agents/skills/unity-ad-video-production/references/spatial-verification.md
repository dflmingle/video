# 专项验收：群体移动与空间交互镜头

仅在当前投放视频确实包含相应空间或群体要求时使用。以下表格是战斗演出实例的提取方式，不是所有视频必备的阶段、人数或行为；通用成片检查见[验收与录制交付](verification.md)。

按本次风险选择检查，不要求每次都建立完整测试系统。复用现有有效检查，只补会漏掉用户问题的证据。表格和测试中的具体阈值来自当前项目要求、角色尺寸和采样条件。

## 剧情契约

在项目现有续作记录里维护以下内容即可；可用范围/事件先后替代精确秒数。

| 阶段或事件 | 必须出现的行为/画面 | 必须保持的不变量 | 允许调整 | 直接证据 |
| --- | --- | --- | --- | --- |
| 开场与入场 | 连续队伍汇入通道 | 可见区域、数量、职责、身体不互穿 | 行距、入场错峰等已允许项 | 实际开场与汇入连续帧、占位检查 |
| 两侧火力差异 | 强火力侧清线，另一侧承压 | 活兵不靠全队倒退表达清线，后续不断流 | 契约窗口内的事件分配 | 各侧前沿、个体运动与有效命中 |
| 换位与特殊单位 | 各自走到指定位置并履行职责 | 保留阶段顺序、合法通道、局部阻挡 | 合法路径和避让方式 | 个体轨迹、目标状态、阶段前后连续帧 |
| 收束 | 指定存活组抵达终点 | 真实人数、分组、到位、结束时机 | 未固定的队内分配 | 各组统计、最大误差、剩余运动、真实播放 |

这只是提取方式；项目没有这些阶段时不要生造。契约需标明哪些来自用户、哪些是推断/可调项。

修改前写清“这次改变什么、可能影响哪条契约、什么证据能证明没破坏”，并保留对应基线。一次局部修改无需创建成套规划文件。

## 直接证据与常见反例

| 要回答的问题 | 直接检查 | 不能充当证明的代理指标 |
| --- | --- | --- |
| 指定敌军是否不再发呆 | 指定时段/兵线的目标、位移、可达性、阻挡/攻击原因及连续画面 | 全军非零运动、我方攻击计数 |
| 是否正确清线 | 两侧分阶段前沿位置、前排真实死亡、后续个体继续向前 | 总死亡数、始终有人近战 |
| 是否走在桥面内 | 权威几何与背景对齐；真实身体沿完整运动扫掠，开放口约定一致 | 没跨左右中线、中心/端点合法 |
| 是否有真实占位 | 敌敌、我我、敌我接触；拥挤及特殊单位推挤；最终显示身体 | 添加 Collider、播放走路动画、只看 ORCA 参数 |
| 是否同基础速度 | 无阻挡可比条件下的小步累计世界路程/时间，剔除无关姿态高度 | UV 常数、曲线端点直线距离、排队者和自由者直接比较 |
| 是否因果正确 | 攻击者、目标、距离/路径、攻击帧、命中与死亡归属 | 任意攻击者存在、粒子已播放、伤亡数符合 |
| 是否阵型适配环境 | 实际截图中位置、密度、轮廓、朝向、环境/HUD遮挡及动态汇流 | Transform 角度误差为零、整体旋转矩形 |
| 是否真实完成结尾 | 每组人数、目标误差、持续到位、停止原因和结束信号 | 存活总数正确、到时冻结、卡片出现 |
| 是否没有无关抖动 | 按实际状态区分站定/行走，对真实旁观者比较位移、朝向和动画 | 所有未攻击者必须静止、整队动画很热闹 |

对新写的断言找反例：用户问题仍存在，它是否还能通过？若能，补直接证据；不要靠增加同类样本数弥补模型不对。

## 连续性与真实画面

- 使用同一相机、分辨率和时间段保留前后对照。先查看实际运行环境生成的图，再制作拼图或 GIF；原始图保留以便放大检查。
- 静态看视觉重心、左右均衡、行列间距、轮廓、遮挡、背景尺度；动态看进入、持续、退出和阶段切换，特别是桥口、换位、接敌、巨人推挤和结尾收束。
- 不只看一个状态的定帧。采样间隔按移动速度、身体尺度与异常持续时间选择；用扫掠/步进检查补充离散帧可能漏掉的短时互穿。
- 单步位移异常需区分瞬移、合法高速和投影变化；检查死亡/删除后活人是否重排，结束前是否被时间冻结。
- 动画、根运动和攻击偏移修改时，必须看最终 Transform/渲染姿态及特效锚点，不能只验模拟位置。
- 主动修复本次画面中明显违反既定约束的问题。助手目视检查通过与用户最终认可分别记录。

## 回放与状态

项目支持暂停、重播、跳转或回退时，比较目标时刻在顺播与直接求值下的关键状态：存活集合、位置、目标、阶段、命中/特效和结束状态。出口锁存、随机相位与缓存也必须可重建；不能拿只适用于单次顺播的锁存修复破坏回退。

不为本次任务擅自新增用户未要求的回放功能。用固定种子或记录输入保证现有模拟可复现，避免不可追溯的随机噪声掩盖停顿。

## 新代码与证据对应

1. 记录本批源码版本/修改时间，发起一次编译或导入，等待完成；检查编译错误及实际加载产物。
2. 对文件请求桥接或共享编辑器，前一请求结束后才提交下一请求。接收状态不等于完成，旧报告存在不代表新请求成功。
3. 能使用请求 ID 与代码版本回显时优先使用；仅有本地工具时，核对源码、程序集、请求、报告和截图时间链，明确其精度限制。
4. 编辑几何后确认派生 Mesh/Collider、ORCA 边和运动缓存来自新轮廓；不可仅刷新可见 Mesh 就执行旧快照检查。
5. 慢预计算期间检查进程、状态和产物进度，避免连续刷新或覆盖请求。没有明确挂死证据，不用重启打断仍有进展的任务。
6. 需要保存场景时确认处于编辑状态且过渡结束，再复位保存，核对实际结果和文件版本。快捷键是切换操作时，不能在未知状态下盲按。

诊断按文件/时间/失败项定向取证，工具输出限量；图片通过路径查看。载荷超限后缩小范围或分批，不原样重试，也不把大图编码进文本。

## 修改范围与回归

- 纯阵型/几何局部修改：直接问题、所有受影响通道/入口、身体占位、推进连续性、相关剧情阶段和结尾路径。
- 全局速度/求解器/目标选择/伤亡或时间线修改：受影响阶段的细查，加完整实际播放、剧情契约与结尾回归。
- 纯文档或技能沉淀：校验文件、引用、语义和适用范围，不启动无关战斗测试。
- 某项新断言失败时，先辨别实现错误、测试对象/模型错误或真实需求替代。调整测试必须写出依据并保留原问题覆盖；不能缩半径、放宽阈值或删失败项凑 PASS。
- 已完成检查只在新修改、失败或未解疑点影响它时重跑。证据目录注明版本，旧失败报告保留背景，不能与本轮报告混用。

## 交付最小信息

说明用户指定对象具体改变了什么、哪些剧情不变量保持、最新直接证据、仍未完成项与实现范围。保留可定位的证据路径，不用大量 PASS 数字代替结果说明。核心失败或必要检查未完成时，不提前称完成。

分享包若在范围内：纳入当前场景、脚本、几何资产、材质/着色器及编辑所需工具；核对隐式依赖与安装条件，按交付风险在独立环境验证导入。给旧导出标明版本，不能假定后续修改会自动进入旧包。
