# V22-R 连续箭雨时长试验（2026-10-30）

本轮交付为三个低成本预览及数据，**不是正式视觉验收通过版本**。基线为 `v22-reference-revision` 的 `b595e1a`，沿用 V22 战斗基础。没有采用 V23 作为开发基础，没有替换既有正式视频。三个时长来自同一次 4 秒真实模拟的不同结束点，均为 720×1080、60fps、正常速度。

## 结论

真实射击已从 0.383 秒开始，首次命中为 0.567 秒，之后持续有多轮真实箭矢。但实际运行截图和编码后画面显示：红军在安全边界前明显拥堵，3×3 编组轮廓在后半段受到破坏。2 秒时存活红兵速度中位数仅 0.341，3.5 秒为 0.292 世界单位/秒。不能用“还有数百名士兵微动”证明仍在持续冲锋。

**A、B、C 均暂不通过完整视觉验收；C 明确不能作为合格的 4 秒正式候选。** A、B 也不是只需用户批准便可直接升格的成片。箭雨覆盖时间增加是真实收益；红军拥堵是本试验引入的退步，必须分别记录。不启动 1440×2160 正式渲染。

- 红方三个军团平移量分别为红 `[0,73.7291207821]`、橙 `[9,70.3046792431]`、黄 `[-12.5,49.8586176712]`；蓝 U 整体平移 `[0,4.3]`。全部在城墙朝镜头的一侧。

- 红方安全约束和接触求解仅在 `safeFrontEngagement` 候选开关启用；原 V22 参数不走该分支。不添加反向击退，死亡根位置固定。

## 拥堵根因与不能采用的结论

为保留全 U 入镜、避开原始场景物体并提前交战，本轮压缩了军团与防线之间的空间。前排受实际防线安全包络限制，后排随后受前排、伤兵和固定尸体占位限制。不同军团纵深推进相互挤压，最终沿防线安全边界形成拥堵，后期无法保持原有小队冲锋轮廓。

名义速度 21.75 下，3.5 秒自由推进约需 76.1 世界单位（尚未扣除启动和受击过程）。目前红方最靠后起点到中间蓝方目标前的安全界限，纵向空间约 50 多单位；其他前排更短。这是本次布局的空间预算冲突，不是宣称所有其他布局都不可能。不能通过降低名义速度、增加击退或让腿原地跑来掩盖。

## 已核对的工程证据及边界

- 241 个模拟帧均包含尸体；保守红蓝表面安全净距下界 ≥4.536。离散帧最近净距为 4.598，额外扣除帧间运动上界得到前述保守数值。
- 红方最小中心间距 0.614405，蓝方 0.614997；相对于圆盘占位半径 0.29 有余量。这不是所有武器和动画网格之间绝不相交的证明。
- 场景阻挡来自原始导出网格的 29 个独立连通部分，在活人高度带求保守凸包；最小有符号净距 0.33255 > 身体半径 0.29。没有用手画矩形替代原始场景边界。
- 浏览器全部 240 帧中，1224 名士兵根位置均在画内，完整 U 可见，无控制台及页面错误。根在画内不等于每个伸出的武器顶点都不裁切。
- 原 V22 红方路径（72 人、30 步）位置/速度逐位相同；原蓝方逐人状态回放和释放相位检查通过，见两个 baseline regression 文件。它们不代表本候选视觉通过。
- 源场景、环境加载器、固定相机定义的 SHA256 与试验前记录相同，见 `proposal.json` 与 `feasibility.json`。

## 视觉核对方法

亲自检查实际浏览器输出的开场、1.5 秒、3 秒静帧；检查编码后 C 的全片时间抽帧及首发 F22–F24、首中 F33–F35 连续帧、尾段 F238–F239，另查看编码后完整末帧。箭矢在编码后仍可见，U 型轮廓保留；红军拥堵和编组轮廓丢失是明确失败项。

`output/v22r-volley/encoded-continuous-and-timeline.jpg` 是实际 MP4 解码画面，不是另行摆拍。当前工具无法向助手提供连续正常速度视频视觉输入，因此**不声称已正常速度观看完整视频，也不声称排除了所有短暂抖动**。全部 MP4 可供正常速度播放。数据、抽帧和正常速度视觉验收不能互相替代。
