# 视频高精度复刻

把可观察事实转成可追溯的重建数据，再验证真实输出。区分原片事实、算法推断、人工修正与程序合成；不要把自动候选当成已经识别的真实对象，也不要把工程运行通过当成视觉复刻通过。

## 开始与方法选择

1. 恢复用户目标、已有授权、基线、指定素材和不可变量。哈希记录源视频、输入数据及已通过版本；实验写入独立目录。已有稳定模块优先复用。
2. 实际解码参考，确定可访问范围、帧率/时间基准、镜头、遮挡与事件阶段，查看代表性连续画面。无法取得后续原片时继续可独立完成的工作，但将缺失覆盖标为 BLOCKED，不编造后续。
3. 读 [方法选择](references/method-selection.md)，按视频类型选择最小有效组合。先以少量可检查样本验证，再扩大范围；失败保留 UNKNOWN 或转 Codex 视觉复核，不反复降低门槛制造成功。
4. 建立具体对象/区域/时间窗的缺口排序和复刻方案。用户已授权实施时直接推进，不把方案文档变成重复审批。

## 重建闭环

### 用户要求替换素材时的强制门禁

先读 [素材来源与替换验收](references/asset-replacement.md)，建立用户指定文件→适配产物→实际加载资源→最终显示实例的来源契约。**替换真实性优先于参考相似度，两者分别验收且必须同时成立。**原片的像素、轮廓、边缘、分割和光流可用于推断位置、分布、朝向、运动、遮挡与事件，以及调试对照；不得把原对象描线、抠图、边缘图、原始帧或直接重绘作为替换对象的最终绘制源，也不得为提高相似度恢复原对象外观。

完整制作前先完成指定素材的静态实例、约一秒连续运动、实际资源与绘制调用来源检查，并验证关闭对象图层后的差异。未证明指定素材真实进入最终画面，或素材缺失/无法加载时，替换项必须 FAIL/BLOCKED；停止依赖该项的扩展并报告，不能用描线占位宣布成功。保留替换素材的辨识特征；其外观与原对象不同造成的像素下降不能触发恢复原对象。不得把逐帧原片描绘作为素材替换架构，即使其媒体与相似度检查通过。

读 [数据契约](references/data-contract.md) 与 [空间和运动](references/reconstruction.md)。按“源帧证据 → 身份 → 显示成员/对象 → 空间分布 → 连续路径 → 事件 → 实际画面对照 → 回归保护”完成每个相关时间窗。

- 单体、群体、显示实例和真实人数分层。群体镜头需要落实内部成员分布，不能只拟合中心；非群体视频无需制造编队或成员系统。
- 首次检测、遮挡恢复、进入、分裂/合并与退出分开；消失不自动解释为死亡。无法识别个体时以可观察区域重建，并标明内部显示成员属于合成表达。
- 轨迹使用统一绝对时间。检查关键帧之间、窗口边界和事件前后；运动路径按累计距离计算，朝向不等于 PCA 主轴。对生命周期适用的对象保持稳定 ID。
- 明确最终数据优先级及缓存依赖。修改后检查最终解析状态和可见像素；绝对成员轨迹覆盖低层布局时必须更新或撤销对应覆盖，不能只改无效参数。
- 参考含重要视觉事件时，读 [视觉事件全生命周期](references/visual-events.md)：从全片发现与时空定位，经阶段/轨迹/持续时间重建、素材或程序效果映射，到实际渲染及最终 MP4 逐事件验收；不能只做起点或主体运动而漏掉传播、结束与消散。无此类事件不强加特效。
- 特效素材适配读 [特效与素材](references/effects-assets.md)。时机、位置、方向、尺度、颜色/亮度和持续以参考证据为准；OBSERVED、INFERRED 与授权增强 SYNTHETIC 分账，不补造不可见阶段。全片含后半段建立事件覆盖表；数量、代码调用和预览均不能代替编码后可见性通过。
- 素材替换走适配层。保持权威轨迹，另处理锚点、单位、轴向、外观比例、根运动和遮挡；换地图时重新验证路径可行性，不能仅换背景后默认兼容。

## 分段验证与交付

读 [验证与迭代](references/validation.md)。先对齐时间和坐标，再比较区域轮廓、密度、身份、轨迹、事件、特效时空分布与构图。保留留出帧和失败分母；平均分不能掩盖关键区域退化。

每次改动确认：目标改善、最终层生效、其他通过窗口未退化、编码产物与实际预览一致。检查连续画面和最终 MP4，说明实际查看范围。覆盖、连续性、视觉保真分别给 PASS/PARTIAL/FAIL/UNKNOWN/BLOCKED；解码通过只证明媒体可读。

Web/Three.js 工程存在且需要运行/录制时，使用同级 [web-game-video-production](../web-game-video-production/SKILL.md) 的实现、浏览器与交付规则，不复制其全文；其他引擎采用适当工具。未安装该 Skill 时按现有工程执行，不把它作为分析脚本的运行依赖。

## 可执行工具

入口：`python <本 Skill 目录>/scripts/replicate.py --help`。用绝对路径调用，无需在 Skill 目录生成项目文件。读 [工具用法与能力边界](references/tools.md) 后按需调用。

- `probe / sample`：元数据、解码、时间戳证据。
- `analyze`：可配置颜色候选、轮廓/PCA、门控匈牙利关联、图像变化及亮区代理；不输出已确认语义或真实人数。
- `register / flow`：两帧 SIFT 仿射或单应配准及留出误差、前后向 LK；失败不输出可采用变换。
- `check / compare`：数据/身份/轨迹检查；时间对齐后的区域 IoU、Chamfer、密度与亮区代理，输出对照视频和窗口指标。
- `render`：轻量二维轮廓/透明精灵适配测试及 H.264 编码；它是诊断工具，不是通用成片引擎。
- `plan`：从分析数据生成需要补齐的实施任务；这是草案，不等于自动理解剧情。

脚本不自动安装依赖。没有合适环境时报告缺项，使用项目现有工具或经授权安装。SIFT/LK、最远点/分位映射和约束拟合有可运行工具；神经检测、语义分割、密集重识别、完整 3D 重建、自动全片纠错仅为条件选项，未打包为既有能力。

历史方法及失败边界见 [审计溯源](references/history.md)。不复制历史项目的数量、阈值、坐标、时间点或专属 ID 为默认值。
