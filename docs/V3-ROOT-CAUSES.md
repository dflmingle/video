# V2→V3 根因、实际修改与证据

## 开场编组错误

保留的 `tools/build_simulation_v2.py` 第 19–25 行用多条横向 lane 排人，第 30–31 行还从 162 名成员池打乱 model/color/cohort。结果把“组内不规则”误作“不同兵种混杂”，与 PDF 第 7 页三个前后纵列大军不符。蓝方配置为九队，也不同于原图七队。

V3 先按 PDF 图建立红后、橙中、黄前三个同轴军团，每军九个小队、内部同兵种。按最新 3×3 指令覆盖第 8 页手写队列，保留 3:4:2 规模关系。初始网格没有随机偏移；个体差异仅在运动中连续生成。证据是 PDF/实际首帧对照及全部成员归属表，而不是颜色数量统计。

## 冲锋速度与动作可读性

V2 基速 6.1、加速 1.15 秒，已经有逐人运动，不能错误归因为完全没有轨迹或一律使用 walk。V3 基速 9.4、加速约 0.8 秒，首帧严格编组，之后由固定成员差异和受约束横向路径产生前沿变化。相机改为锁定，避免相机运动抵消屏幕上可见推进。

V2 `src/assets-v2.js` 已有原生 move 和跨步叠加；V3 增加受约束足部 IK 与 32 姿态间插值，减少姿态跳变、改善支撑。最初支撑占比 0.26 让目标跨步超出短肢体可达范围；缩短至 0.18 后，相同诊断方法测得 sword/flail 平均残余滑移从约 31% 降至 22%，samurai 从约 17% 降至 3.4%。支撑仍不完全接地，不能记成零滑步。指定连枷没有独立 walk 片段，move/walk 元数据映射相同，不能凭标签声明它具有专门跑步片段。最终使用原 move 加跨步适配，而非仅提高方阵平移倍速。

无战斗完整预览、前中后排速度和累计路径、最终编码奔跑局部共同验证。仍有足部残余滑移，保留 PARTIAL；“速度提高”不能直接当作艺术真实感 PASS。

## 箭矢中段不清楚

V2 飞行时间在 `tools/build_simulation_v2.py` 第 78 行夹到 0.48–1.3 秒。V3 用空间距离/速度，原生手部发射点，独立箭杆/头/羽片和更短尾迹，减少漂浮长线观感。命中与死亡继续绑定真实目标。最终 MP4 抽帧显示有方向的传播和目标闪白/倒地；密集处单体可读性仍 PARTIAL。

## 尾段事件被输出范围截断

最终编码审查发现原 V3 末段不再启动新射击。原因是生成器 `hf >= N-2` 时直接丢弃候选事件，只保留镜头内能命中的箭，并非粒子或编码漏录。修复保留 739 次镜头内命中及原轨迹，增加 124 次切镜时仍在飞行的射击，标记 IN_FLIGHT_AT_CUT。其镜头外目标点为显式预测，不记录虚假的命中/伤亡。渲染器统一时间自然保留尾段拉弓、发射、在途箭矢；声音编码跳过片外命中。验证最终渲染每帧实际箭矢数与事件账本一致，最后一帧仍有 124 支在途箭，最后一次释放发生在 6.567 秒。

## 无效方向与保留限制

随机混兵、依靠相机运动制造推进、仅查事件计数均不能解决用户问题。长跨步加足部约束也未达到零滑步，报告保留原始残余，不修改阈值伪造通过。诊断密度网格曾遗漏后军纵深，已扩展至全区域并断言覆盖所有活人；此修复只改变统计，不改变角色画面。

所有修改均在 V3 独立目录。V2 原 MP4 与保存基线哈希一致。未编辑 RiverBattle 或火柴人工程。项目为脚本编排演出，不声称自主 AI。
