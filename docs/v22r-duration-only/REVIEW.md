# V22-R 仅延长结束时间复核（2026-10-30）

本轮按用户最新要求，以原约 2.2 秒视频实际使用的 `variants/V22R-overlap` 为唯一基线。只在独立副本 `V22R-duration-only` 中将请求时长由 2.2 改为 3.5 秒。未开启上一轮 `parallelAssemblyFire`、`safeFrontEngagement`，未平移军团、改变集结距离、提前准备或射击。原版视频和模拟文件均未覆盖。

**结果：仅延长时长仍被原安全检测截断至 2.20 秒，无法交付合格的 2.2–3.5 秒后续片段。** 公共区间战斗完全复现；没有使用冻结、漏斗约束、击退或循环制造额外画面。

## 原版为什么结束

原成片渲染器 `tools/render_final_castle_v22r.mjs` 从原 `params.json` 读取 2.2 秒，在 60fps 下输出 132 帧 F0–F131，即采样时刻 0–2.1833 秒。模拟另有 F132（t=2.2 秒）安全边界状态。不是剪辑软件在一段已安全完成的长视频里任意裁掉后续。

原文件里 `autoCut=true`。本轮把相同参数的请求时长改成 3.5 后，复现了以下截止：

| 检查 | 结果 |
|---|---:|
| 最后接受的模拟状态 | F132 / 2.2000 秒 |
| 首个被拒绝的状态 | F133 / 2.2167 秒 |
| 最后接受状态的表面净距 | 4.514668 |
| 被拒绝状态端点的表面净距 | 4.171561 |
| 通向被拒绝状态的帧间保守净距下界 | 3.957281 |
| 最低净距要求 | 4.0 |
| 原截断额外缓冲 | 0.05 |

原检测公式为 `min(前后端点最近中心距) - 0.5 × (蓝方最大步长 + 红方最大步长) - 2 × 3.1`，并在小于 `4.0+0.05` 时截止。该步蓝/红最大步长分别为 0.028283 / 0.400276。

**4.171561 是端点距离，3.957281 是保守下界，不可把后者说成已经观测到身体接触。** 本轮没有放宽检测、关闭安全约束，也没有声称 2.20 是经过精确连续碰撞求解证明的绝对最晚时间；它是当前原有检测支持的最后安全状态。即使将来单独批准更精确的扫掠距离检测，也不能据此推断能额外获得 1.3 秒。

原历史运行没有独立的终止原因文件；本轮同参数长时长复算得到完全相同的 133 帧和完整模拟 JSON，并新增 `termination-evidence.json` 记录第一次拒绝。这是本轮可直接复核的证据。

## 公共区间是否改坏

- 原数据五个主要文件哈希与原视频 `render-audit.json` 的记录完全一致，确认取到的不是另一版 V22。
- 重新模拟后，完整 `simulation.json` 与原版完全相同，包括所有士兵资料、射击事件、起点、目的点、释放和预计命中时间。
- 133 帧、1224 人的世界坐标、蓝方个人控制、红方个人控制、步态距离/周期、受击记录、个人状态、局部避让和反应目标均逐位一致，最大数值差为 0。
- 场景、材质绑定、灯光设置及相机每帧参数一致。相机定义、原生场景清单、环境加载器内容与 `b595e1a` 一致（Git 签出换行差异单列）。
- 重新渲染全部 132 个公共视频帧，在 1440×2160 下逐帧比较。单帧平均像素通道差最大 0.000030114（0–255 尺度），最大单通道差为 9；没有假称每个像素逐位相同。逐帧结果见 `pixel-and-world-every-frame.csv`。
- 以上证明本轮没有新增上一轮的漏斗形堆积逻辑；并不代表原版既有的裁切、穿越城墙、远近阵型变化已经修复。用户要求本轮不改场景与初始布局，故没有顺手改这些内容。

## 3–4 秒为何需要放宽至少一项条件

原冲锋继续沿原路径接近已集结防线，净距正在快速减少；首次计划命中还没到，原安全截止已发生。在初始布局、行军轨迹、逐人速度与射击时序全不变的条件下，不能单靠编码时长增加有效画面。

最后两个接受状态的最近净距变化对应约 20.72 世界单位/秒。若只作局部线性预算，额外维持到 3.0 / 3.5 / 4.0 秒分别需要约 16.6 / 26.9 / 37.3 单位的额外接近空间。**这是用最后一步作的量级估计，不是重新模拟结果，也不是已验证的最小平移量。** 不能将它当作直接挪兵的依据。

可能改变的条件及牵连如下，均未实施：

| 条件变化 | 为什么不能视作本轮“只延长结束时间” |
|---|---|
| 增大军团初始距离 | 违反布局冻结，且会改变进入射程与射击时间 |
| 接近防线后局部减速、转向或改路径 | 改变后续世界轨迹；须独立验证，不可重新引入上一轮堆积 |
| 调整蓝方防线或集结目标 | 违反原集结路径和当前布局冻结 |
| 提前准备/放箭、改变射程或攻速 | 本轮明确禁止 |
| 降低 4.0 安全净距、冻结、原地跑或增大击退 | 本轮明确禁止，不能采用 |

可以继续不动的内容包括已确认的场景、灯光、固定相机、原攻击周期、箭速、轻微受击/倒地流程。若将来允许单独研究后续运动约束，应以 t≤2.2 秒全部数据保持一致作为硬回归条件；本轮没有自行添加这项修复。
