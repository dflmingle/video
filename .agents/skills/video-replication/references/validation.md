# 窗口验收与退化回滚

## 对齐先于误差

记录源视频 hash、PTS/帧号、裁图、分析缩放、相机补偿矩阵和 render 时间映射。`compare` 的映射为 `candidate_t = scale * source_t + offset`，最近帧取整并输出实际时间。先用多个事件/地标验证，不默认为零偏移。不同镜头分开对齐，不用任意形变消除待测对象的真实误差。

`compare` 的坐标矩阵在配置的共同 canvas 像素中将 candidate 映到 source；resize 仅用于声明的分析画幅，不改变项目相机。边缘越界和空掩膜应记录，不能删掉失败帧。VFR/PTS 无法验证时先做带映射的分析副本，保留原片。

## 指标与目视共同决定

| 验收对象 | 适用指标 | 必看画面/限制 |
| --- | --- | --- |
| 空间与结构 | 区域 IoU、轮廓 Chamfer、中心/轴/范围、密度场、NN/邻队距离 | 对象角色/脚点与源图形不一定像素相同；检查布局、缺口、遮挡、构图 |
| 身份与成员 | 稳定 ID 集合、归属账本、源与显示数量分别统计 | 组件数不等于人数；遮挡后 re-ID 未确认不强判 |
| 连续运动 | 累计路径、速度/加速度、跳变数、边界差、帧间最小间距 | 包含头中尾/局部成员与接触过程，不能仅测中心 |
| 事件与特效 | 区域时刻/并发、活动持续、亮区/烟覆盖及强度分位 | 代理不当事件数；看组成、先后、扩散和退出 |
| 生命周期 | 受击后门禁、死亡位置、淡出/隐藏、不复活、不重排 | 保留原稳定模块；新脚本不能凭 count 证明死亡自然 |
| 成片 | 实际解码帧数/时长、黑帧/重复帧候选、压缩细节 | 有意黑场/静止段可正确，标注设计依据，不机械判错 |

按动作速度决定采样。常规均匀抽样加快速变化加密；最终关键动态检查连续帧。不能把导出所有帧说成目视逐帧看完。记录实际浏览器/引擎预览、最终视频解码和目视范围，声音未听不称听验通过。

存在重要视觉事件时，执行 [逐事件门槛](visual-events.md#逐事件验收门槛)，包括后半段和跨窗口残留。每条只验参考支持的阶段；未人工查看的编码证据不能由全局“已查看”标志批量转为 PASS。素材替换真实性与事件保真仍独立验收。

## 每窗闭环

保存 baseline 输入/状态/截图/编码哈希 → 排名具体对象和误差 → 最小数据修正 → 更新最终生效缓存 → 渲染本窗及边界 → 对照源片和 baseline → 留出指标与连续画面 → 接受或回滚。其他通过窗口做针对性回归；全局时间/渲染变化要复查全流程。

项目门槛按源分辨率、对象尺度、观测误差和用户要求制定；脚本不给通用“高精度及格线”。低风险局部修改无需反复全片重渲染，但最终交付的编码视频必须来自所选集成版本。

并行工作按互不冲突的区域/对象/数据文件隔离，共用 ID、时间与映射。前段终态未定就标待集成；主线程统一合并、最终写入层和 GPU 渲染队列。不让两个生成器同时覆盖同缓存。

## 分开报告

- COVERAGE：可访问参考范围是否都有证据支持的内容，缺失部分明确 BLOCKED。
- CONTINUITY：身份、路径、姿态、事件及生命周期跨窗是否连续；采样测试范围清楚。
- VISUAL FIDELITY：每个关键区域/阶段达到什么程度，剩余误差逐项说明。
- ENGINEERING：加载、解码、状态、数量、确定性和不变量。

每项给 PASS/PARTIAL/FAIL/UNKNOWN/BLOCKED，并附当前版本证据。工程 PASS 不推导视觉 PASS；用户认可观感也不能改写未通过的历史细项。最后交付文件、运行方式、窗口指标、修正与回滚、未知及下一步，避免空泛“有所改善”。
