# 从实际返工提炼的制作方法

## 跨题材经验索引

这些经验适用于 Unity 投放视频；下文保留战斗场景作为证据，不要求后续视频采用同样题材或算法。

| 可迁移的难点 | 制作中的处理原则 | 来源案例 |
| --- | --- | --- |
| 修错对象或阶段 | 锁定用户指定的主体、时段与画面，指标要直接回答问题 | C01 |
| 局部流畅破坏剧情 | 同时保护叙事顺序、职责、状态变化和结尾，先查模型 | C02、C03 |
| 编排与表现互相牵制 | 用可行的路径、时机和动作实现事件，不从终点倒推不可信过程 | C03、C07 |
| 数据正确但构图仍差 | 同时审位置、朝向、密度、轮廓、镜头和UI，查看动态变化 | C04 |
| 静态美术缺空间依据 | 先标定可编辑空间，再让相关系统共享数据；硬约束后查副作用 | C05 |
| 特殊角色待遇只存在参数里 | 优先级必须落实到真正生效的求解或状态层 | C06 |
| 结果计数代替完成 | 结束依赖真实画面状态，而非只看时间、数量或卡片 | C07 |
| 内部状态与最终画面脱节 | 验最终姿态、偏移与效果，区分参与者和旁观者 | C08 |
| 工具动作被误当完成 | 确认新版本加载、任务完成、产物对应及保存状态 | C09 |
| 历史要求被当现行规则 | 明确需求替代、实现范围和验收版本，不照搬旧效果 | C10 |

优先读与本次症状相符的条目。案例中的“真实”指满足当前连续镜头及用户要求的因果/空间一致性，不要求所有广告都采用真实游戏模拟；用户明确选择的剪辑、夸张和定格可以照常使用。

## 原始失败链

来源：2026-10-09 至 2026-10-14 的双桥战斗修改记录及跨项目案例库。这里提取方法，不提供其他项目的默认时刻、人数或地形参数。后续实现通过了相应版本的工程检查及助手看图；不等于用户已最终认可全部观感，也不保证其他地图有效。

按症状阅读对应条目；同一症状返工时，不只重读“有效方法”，也读误判和新增问题。

## C01 对象错了，做得再多也没解决

- **误判**：用户说右路敌军停着挨打，被理解为我方盾兵没攻击。
- **失败修改**：补我方攻击，增加每兵控制对象，用“全军仍有人移动”作验收。
- **新增问题**：旁支系统改善，原兵线仍停顿；完成报告与用户看到的画面不一致。
- **根因**：对象、阶段与指标脱节；没有检查指定前排的真实目标和状态。
- **有效方法**：分别跟踪指定前排、后续队列、攻击目标和阻挡原因，区分推进、接敌、等待与清桥阶段。
- **防复发**：问“原问题存在时，本指标是否仍能通过？”全军计数不能证明局部正常；清空桥面时不能要求隔空近战。
- **边界**：补攻击动画不能证明伤害、目标可达或自主 AI 已完成。

## C02 消除停顿，却破坏清线剧情

- **误判**：把兵线控制理解成前沿必须持续前进。
- **失败修改**：始终让前排补齐原前沿，拉近敌军保证近战；死亡后按剩余人数重排。
- **新增问题**：火力再强，桥面仍被同一条前沿占据；清桥与两路差异消失。
- **根因**：混淆个体方向与群体边界，队列模型抵消了火力造成的空间变化。
- **有效方法**：保留活单位各自的推进状态，杀掉实际前排；后续继续向前，但由不同成员构成的新前沿可以后移。
- **防复发**：同时检查阶段前沿变化、存活单位不因火力倒退、后续连续推进、真实命中归属；不能只数总伤亡。
- **边界**：这适用于清线演出；用户明确要求战术撤退时，应另建撤退命令和合法路径。

## C03 为了密集连续，连速度和因果一起改坏

- **误判**：用个人预定死亡时刻决定追赶速度；以为同一 UV 速度就是同一世界速度。
- **失败修改**：出生、后方加速、行列和积分同时修改；测试又用弯路端点直线距离衡量速度。
- **新增问题**：慢后排夹着零散快兵、桥口重叠、预定击杀找不到有效攻击者；任意挑攻击者会继续掩盖错误。
- **根因**：伤亡编排反向支配导航，坐标尺度与路程度量混用，多项改动无法归因。
- **有效方法**：普通行军使用统一基础世界速度与累计路径里程；火力事件在符合职责与可达性的实际前沿目标中分配；小批调整入口与供给。
- **防复发**：在相同无阻挡条件下比较累计世界路程；另查等待、碰撞、前沿和命中因果；契约事件无法成立时诊断可行性，不远处杀人凑数。
- **边界**：世界速度一致不要求屏幕投影速度一致；射程、职责和精确受害者是否固定取决于本次契约。

## C04 朝向正确，阵型仍不适配环境

- **误判**：把“队伍与桥协调”仅理解为模型旋转角度。
- **失败修改**：只转朝向，随后整体斜切矩形，再缩纵深避免遮挡。
- **新增问题**：出生与推进仍沿屏幕轴，轮廓左高右低、顶进 HUD；后方割裂或像一整块斜板。
- **根因**：未同时设计位置基底、连续人群、轮廓与场景可占区域。
- **有效方法**：纵列沿通道局部轴，横向按世界尺度布置；根据河岸、岩壁、镜头和 HUD 调整分布，近入口逐渐汇流。
- **防复发**：保存基线，亲自查看开场及汇入连续帧；开场放大看边缘、最后一排与 HUD，不能只看缩略拼图。
- **边界**：弧形后沿、收拢两翼只是该场景的选择，不是通用阵型公式；助手看图不代表用户审美验收。

## C05 约束中心点后，身体仍出桥；加硬边界又卡人

- **误判**：没串左右路、中心没越界就等于身体合法；以为添加 Collider 会自动影响自写 ORCA。
- **失败修改**：反复改桥头坐标；中心点检查通过后，直接按身体半径截断所有越界位移。
- **新增问题**：真正身体边缘出桥；硬截断后巨人推挤导致重叠，结尾角色卡在桥口；将开放河岸当桥内又产生误报。
- **根因**：空间数据多源，目标、运动、推挤与整队路径使用不同边界/半径/入口约定。
- **有效方法**：一份可编辑轮廓派生 Mesh、Collider、ORCA 侧边与路径；开放桥口，做全身体扫掠；沿边滑行并给侧边角色合法入口对齐路径。
- **防复发**：同时验实际几何对齐、完整身体边界、占位、无卡住和结尾到位；检查入口/出口及编辑后的缓存刷新。查询依赖 Collider 时做实际射线/物理验证。
- **边界**：圆形地面占位不等于模型所有外轮廓；直桥凸四边形不能直接处理任意弯桥或多层导航。

## C06 巨人有优先级，还是被小兵挡住

- **误判**：取消巨人 ORCA 限制或增加让路偏好就能保证前进。
- **失败修改**：只改速度偏好，接触保护仍对称地停止双方。
- **新增问题**：巨人动画正常但没有实际到前沿；简单移开邻兵又可能出桥或重叠第三人。
- **根因**：优先级未进入实际位置接触求解；一对角色的修正会产生新的邻接接触。
- **有效方法**：沿合法路线推进，接触位移按授权优先级传给小兵及邻兵，继续统一迭代边界和接触；边缘需要可行滑行。
- **防复发**：直接检查巨人的实际进度和连续帧、邻兵身体与桥边、逐步推挤原因；不能给全部反向移动免检，也不能缩半径过关。
- **边界**：这是具有特定设计优先级的推挤；普通角色不能自动获得同样权限。

## C07 人数对了，结尾却没真正完成

- **误判**：到截止时间冻结角色，就等于完成收束；人数正确就等于分组站齐。
- **失败修改**：固定时刻停止移动，所有人直奔终点；用当前位置反复切换出桥与整队目标。
- **新增问题**：一人卡在桥口或被已站定队友挡住，目标往返切换，分组不齐但结束卡片已出现。
- **根因**：终点与通道阶段不稳定，路径只看中心，完成条件只看时间/人数。
- **有效方法**：稳定分配终点，经合法出口后绕开站定占位；出桥阶段单向锁存，整队路径使用身体约束；完成信号依据实际到位。
- **防复发**：验每组人数、最大目标误差、剩余移动、入场连续性及结束卡片时机；时间线跳转/回退能正确重建锁存状态。
- **边界**：用户允许动态阵型时可用其他分配方式；固定截止时刻若不可达，应诊断上游供给与路径，不能隐藏未到位。

## C08 模拟零重叠，最终显示仍互穿

- **误判**：模拟 Position 快照通过就能代表画面；未攻击的人一定是静止旁观者。
- **失败修改**：只验模拟位置，另给近战增加渲染前踏；旁观者测试仅按攻击标记分类。
- **新增问题**：多个盾兵同时前踏互穿，武器/命中位置与修正后角色脱节；正常换位者被误报为旁观者乱动。
- **根因**：渲染偏移绕过运动约束，测试分类与权威路径状态不同。
- **有效方法**：对同时发生的最终位移做共享相对扫掠，角色和效果使用同一修正；按真实行走与站定状态区分对象。
- **防复发**：模拟位置与最终 Transform 都验；命中距离与特效锚点一致；对真正站定且未参与的角色检查无因位移、转向和换帧。
- **边界**：允许的动画视觉外扩与地面身体占位需明确区分；不能把所有肢体相交机械定义为占位失败。

## C09 旧 PASS 与保存状态制造假完成

- **误判**：发起刷新等于新程序集加载；写出播放结果等于已退出播放。
- **失败修改**：编辑器忙时连续刷新、覆盖文件请求、同时排多个审计；报告一写出便复位保存。
- **新增问题**：用旧代码和旧报告证明新修改，待执行任务被覆盖；保存仍处于播放/退出过渡而失败。
- **根因**：请求接收、任务执行、产物完成、编辑器状态切换被当成同一事件。
- **有效方法**：每批代码刷新一次并确认加载，桥接按依赖串行，核对请求/版本/产物；退出状态完成后再复位保存。
- **防复发**：报告与截图属于同一运行版；检查真正完成状态、错误及最新保存结果，不能仅检查文件存在。
- **边界**：本地时间戳是最低证据，缓存或跨机环境应使用版本/哈希；慢预计算不能未经检查就误判为卡死。

## C10 历史需求和实现能力被误当现行事实

- **误判**：旧报告写“已完成”就覆盖新失败；旧死亡方式仍适用于用户的新参考。
- **失败修改**：继续沿用过时缩放/贴地规则；回退旧流程后把未完成的碰撞需求也标解决；以自写控制器或 Collider 声称完整自主 AI。
- **新增问题**：新效果缺少指定组成部分，活人和旁观者受影响；实际能力与交付描述不符。
- **根因**：未记录需求替代关系与版本边界，把工程结果、审美认可和实现范围混在一起。
- **有效方法**：维护现行契约及替代关系，按参考拆分必要阶段；分别记录剧情编排、局部模拟与未实现能力，回退后重新核对未完成项。
- **防复发**：每条完成结论能指向现行要求和对应版本证据；分享包与最新场景明确区分；没有用户认可就不记为最终成功。
- **边界**：新要求不代表推翻全部旧约束，仅替代明确发生冲突的部分。
