## 真实建筑组与障碍数据

来源始终为 `public/native-scenes/CastleExterior-scene/manifest.json` 原 Unity 导出。原模型顶点、材质、贴图文件不改、不缩放。

整体移动的原层级：`CastleExterior_Grp/CastleExterior_Dec/CastleExterior_Building` 下 `polySurface18` 与 `rock.016`，包括墙、城门、塔楼和关联建筑。墙脚四个 Stakes 对象与建筑使用相同位移：Stakes_01/02 的 `(3)`、`(2)`。确切完整路径在各候选 `sceneLayout.objectPaths`。

地面 `CastleExterior_Land`、树木、独立围栏/木桩、花草及隐藏的 Gird 维持原矩阵。地面是独立连续原生网格，不随城堡移动；没有修改地形或留下移动地块。真实浏览器开场图已核对墙脚、木桩和地面，没有看见悬空或新地面缺口。

`src/environment-native-v22.js` 仅新增按候选参数应用刚性矩阵的入口。`tools/scene_occupancy_v22r.py` 让原网格障碍截面接受相同变换；各版29个真实网格障碍足迹写入 `E*-obstacle-footprints.json`。浏览器34个对象世界矩阵逐项与预期比较，6个对象同步移动，其余不动，缩放与材质绑定保持一致。

这里交付的是沿用项目现有 Three.js 预计算视频管线的真实 Unity 网格场景；障碍数据是本管线的真实网格截面足迹与全帧轨迹审计，不冒称正在 Unity PhysX 中运行或已修改原生 `.unity` 场景碰撞器。原模拟没有新增环境寻路/碰撞规则；候选必须以轨迹未穿越移动后障碍的检查证明可行。

## 战斗保留与已知限制

`setup.json` 锁定13个战斗、相机、姿态及原资源文件哈希，并与 `a64a654` 内容比较；没有改变红军速度/加速度、攻击准备/周期/射程/箭速、第一波规则、命中/闪白/受伤/死亡、近战目标选择或胜负判定。

布局变动会自然改变具体目标分配、事件时间与伤亡。没有用提前放箭、加速或减速补偿。E2红军0.3秒存活速度中位数21.694世界单位/秒，原有高速冲锋保留。

只改初始距离不会消除原近战弧形混战；从E1/E2编码画面仍可见该形态。也不会得到几秒钟的整齐远距离奔跑：E2首次进入近战范围约0.517秒，首次近战伤害0.800秒，原因是原本高速冲锋和蓝方同时集结。2秒画面已经是箭雨尾段与近战重叠，不能伪称全程纯箭雨。

固定镜头的后期追击出画仍需如实报告。只保证经过测量和截图核对的开场主要军团完整入画，不能把脚底投影检查当完整角色轮廓，也不宣称全程所有士兵都在画内。

旧 D2 场景回归34个世界矩阵完全一致。与先前PNG比较有43个栅格像素差异（总计777600像素），集中于场景上部边缘；因此报告矩阵/数据不变，不报告逐像素相同。
